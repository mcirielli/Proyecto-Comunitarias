\# Instrucciones para Codex — Comunitarias



\## Contexto



Proyecto académico de Proceso de Desarrollo de Software de UADE.



Equipo de cuatro estudiantes. Presentación prevista para el 31 de octubre de 2026.



\## Documentación obligatoria



Antes de proponer arquitectura o generar código:



1\. Leer `context/SUPERPROMPT.md`.

2\. Revisar los documentos de `context/entregas`.

3\. Utilizar `context/material-uade` como referencia académica cuando corresponda.

4\. Identificar contradicciones entre los documentos y el superprompt.

5\. Priorizar los requisitos académicos ya entregados.



\## Stack tecnológico



\- Java 21 y Spring Boot.

\- React, Vite y TypeScript.

\- PostgreSQL en Supabase.

\- Maven y JUnit 5.

\- Git y GitHub.



\## Reglas de desarrollo



\- Trabajar de forma incremental.

\- Respetar SOLID y la separación de responsabilidades.

\- Implementar los patrones acordados mediante código real.

\- Evitar complejidad innecesaria.

\- No modificar funcionalidades existentes sin justificación.

\- No agregar dependencias sin explicar su necesidad.

\- No almacenar credenciales ni secretos en el repositorio.

\- Crear pruebas para las reglas de negocio.

\- Mantener actualizada la documentación.



\## Forma de trabajo



Antes de implementar una etapa:



1\. Explicar el objetivo.

2\. Identificar archivos afectados.

3\. Proponer los cambios.

4\. Esperar aprobación cuando se trate de decisiones arquitectónicas relevantes.

5\. Implementar solamente la etapa autorizada.

6\. Ejecutar las verificaciones disponibles.

7\. Informar resultados y errores pendientes.



\## Restricción inicial



No generar la aplicación completa automáticamente.



Primero analizar los documentos, validar la arquitectura, definir el modelo de datos y proponer un backlog para cuatro integrantes.
